## 1. What twinBook is, in short

An Android app for using Facebook without ads and trackers. It embeds GeckoView
(Firefox's engine) with a built-in WebExtension called twin-bridge that filters
Facebook's responses at the network layer, and it renders the main screens as native
Jetpack Compose UI. M0 builds none of that. M0 delivers the ground everything else
stands on: a reproducible toolchain, a multi-module project that builds, a TypeScript
workspace for the extension whose output is packaged into the APK, scripts to run
checks and drive an emulator, and proof that all of it works on this machine.

Why this matters: every later milestone is run by an agent like you, from a prompt
like this, with no memory of earlier work. They will rely on your scripts and your
`docs/SETUP.md` to build, test and launch without rediscovering anything. Optimize for
that reader.

### 4.1 Reproducible toolchain

Write `tools/setup-toolchain.sh`. It must be idempotent, need no sudo, and bring a
fresh checkout on this machine to a building state. Run it yourself. It installs:

- Temurin JDK 21 under `~/.jdks/`.
- Android SDK under `~/Android/Sdk`: command-line tools, platform-tools, the platform
  and build tools the build needs, the emulator, and the system image listed above.
  Accept the SDK licenses non-interactively. The owner authorizes this by issuing
  this prompt.
- An AVD named `twinbook_api36` (phone profile, x86_64), sized for this machine.

Write `tools/env.sh`, meant to be sourced. It exports `JAVA_HOME`, `ANDROID_HOME`, and
a PATH that puts the JDK, the SDK's platform-tools, emulator and command-line tools,
and the nvm Node directory first. Every other script sources it, so scripts work from
a non-interactive shell with no profile. Add `.nvmrc` with the Node major version.

`local.properties` stays untracked. The build must work with only `tools/env.sh`
sourced.

### 4.2 Gradle project

- Gradle wrapper committed. Version catalog at `gradle/libs.versions.toml` holding
  every version. Configuration cache and build cache enabled if they work cleanly.
- Modules:
  - `:app`: Android application, Jetpack Compose with Material 3, single activity.
  - `:engine`: Android library. Placeholder for the GeckoView wrapper. One small class
    with a function the app calls, so the wiring is real.
  - `:data`: pure Kotlin JVM library, no Android dependency. Placeholder for models,
    normalizer and ad classifier. One small class with a function the app calls.
- Identifiers: namespace and application ID `io.github.chabiroael.twinbook`, debug
  builds get the suffix `.debug` so debug and release can coexist. This ID is
  provisional and may change before release.
- `minSdk` 26. `compileSdk` and `targetSdk` at the newest stable platform AGP supports
  without warnings. Java and Kotlin bytecode target 17, built with the JDK 21 toolchain.
- ABI handling is not needed yet. Do not add ABI splits.
- The app shows one placeholder screen. It must display: the app name, the app version,
  one line produced by `:engine`, one line produced by `:data`, and the version string
  read at runtime from the packaged extension manifest (see 4.3). This screen is the
  visual proof that all modules and the extension pipeline are wired. Keep it plain.
- Tests:
  - `:data`: at least one JVM unit test.
  - `:engine`: at least one local unit test.
  - `:app`: one instrumented Compose UI test that asserts the placeholder screen shows
    the `:engine` line, the `:data` line and the extension version. This proves the
    instrumented-test path that M1 depends on.
- Android lint runs as part of `check`. No extra linters or formatters in M0.

### 4.3 Extension workspace

Directory `extension/`, the future twin-bridge WebExtension.

- `package.json` (private), TypeScript in strict mode, esbuild for bundling, Vitest
  for tests, all as local dev dependencies with a committed lockfile.
- `manifest.json`: Manifest V2, because the design needs blocking webRequest on Gecko.
  Gecko ID `twin-bridge@twinbook`. Name, version, one background script. No
  permissions yet. They are added in M1 when they are used.
- `src/background.ts`: minimal, logs one line on startup.
- `src/lib/`: one real utility with tests, so the test path is not a toy. Implement
  `stripJsonGuard(text)`: Facebook prefixes JSON responses with the guard
  `for (;;);` (also seen as `for(;;);`). The function removes one leading guard if
  present and returns the rest unchanged otherwise. Cover both spellings, absence,
  leading whitespace, and a guard appearing later in the text, which must not be
  touched.
- npm scripts: `build` (bundle to `extension/dist/` with the manifest copied in),
  `test`, `typecheck`, `lint:ext` (run `web-ext lint` on `dist/`), and `check` that
  runs typecheck, tests, build and the extension lint.
- Packaging: a Gradle task in `:app` builds the extension and adds `extension/dist/`
  to the APK assets at `extensions/twin-bridge/`. Declare task inputs and outputs so
  it is skipped when nothing changed and rerun when extension sources change. If Node
  is missing the task fails with a clear message pointing to `tools/env.sh`.
  `dist/` and `node_modules/` are not committed.
