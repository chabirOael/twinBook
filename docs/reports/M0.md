## 6. Deviations

1. **The SDK is installed with `android sdk install`, not `sdkmanager`.** cmdline-tools
   23 has deprecated `sdkmanager`, which now forwards to the new Android CLI. On first use
   the CLI downloads a 90 MB binary to `~/.android/bin/android-cli`. Package paths use
   `/`, and the CLI accepts the license on install (it writes
   `licenses/android-sdk-license`). `sdkmanager --licenses` now only prints "The
   --licenses option is no longer needed". The script detects installed packages by the
   presence of `package.xml`, because the `--list_installed` output format changed.
2. **compileSdk is 37 with minor API level 2**, set through the AGP 9 DSL:
   `compileSdk { version = release(37) { minorApiLevel = 2 } }`. Platform 37.2 is stable
   on channel 0 and builds without warnings. The script installs only `android-37.2`. I
   removed `android-37.0` from the machine so the build is proven to work with exactly
   what the script installs.
3. **Gradle heap is 2 GB and the Kotlin daemon 1 GB**, not about 3 GB. With 3 GB / 1.5 GB
   the dry run peaked at 10.1 GB used plus 1.8 GB swap. At 2 GB / 1 GB the peak was
   8.9 GB plus 0.86 GB swap, and every build passed. `org.gradle.workers.max=4`.
4. **The extension manifest has
   `browser_specific_settings.gecko.data_collection_permissions: {"required": ["none"]}`.**
   web-ext 10.7 warns `MISSING_DATA_COLLECTION_PERMISSIONS` without it. `none` is
   accurate: twin-bridge sends no data to anyone. It is metadata, not a permission.
5. **Extra app files to make lint clean:** `data_extraction_rules.xml` and
   `backup_rules.xml` exclude everything from cloud backup and device transfer, which also
   matters once the app holds a logged-in session. I added a plain placeholder adaptive
   icon (two rings) for `MissingApplicationIcon`. `buildConfig` is enabled so the screen
   can show `VERSION_NAME`/`VERSION_CODE`.
6. **Android lint on `:data`** goes through the standalone `com.android.lint` plugin,
   because a JVM module gets no lint from AGP otherwise. `:data:lint` runs in `check`.
7. **Plugin repositories are `google()` and `mavenCentral()` only**, with no Gradle
   Plugin Portal, to stay on the hosts listed as reachable. All plugins resolve from
   those two.
8. **Two Gradle tasks instead of one** for packaging. `:app:buildTwinBridge` runs
   `npm ci` if needed, then `npm run build`, with output `extension/dist`.
   `:app:twinBridgeAssets<Variant>` copies dist into a generated assets directory under
   `extensions/twin-bridge/`. It is registered through
   `variant.sources.assets.addGeneratedSourceDirectory`. One task cannot be registered as
   the generated source of several variants, because AGP would set its output location
   once per variant.
9. **`stripJsonGuard` and leading whitespace:** when a guard follows leading whitespace,
   the function removes the whitespace and the guard. When there is no guard, the text
   is returned unchanged, whitespace included. The prompt did not specify this.
10. **`env.sh` also exports `ANDROID_SDK_ROOT`**, which older emulator code paths still
    read, plus `TWINBOOK_AVD`, `TWINBOOK_EMULATOR_PORT` and `TWINBOOK_EMULATOR_SERIAL`.
11. **Commit trailers:** the commits on `m0-skeleton` end with a `Co-Authored-By: Claude`
    trailer. The `main` docs commit has exactly the message the prompt gave and no
    trailer.
12. **LICENSE** is the current text from gnu.org (`gpl-3.0.txt`). It differs from
    Ubuntu's `/usr/share/common-licenses/GPL-3` only in `http` versus `https` URLs.

## 7. Problems and risks

- **KVM access will break after a WSL restart.** `/dev/kvm` is currently
  `crw-rw-rw- root kvm`, so it works, but user `wael` is still not in group `kvm`
  (`id` shows no `kvm`). The mode 666 looks like the per-boot `chmod` workaround and will
  be lost on the next WSL restart. Owner fix: `sudo usermod -aG kvm $USER`, then
  `wsl --shutdown`.
- **The first setup run failed.** It stopped silently in the license step: a pipeline
  under `pipefail` failed because `licenses/` did not exist yet. I fixed it, and that
  code was later replaced (deviation 1).
- **The Android CLI updates itself.** It writes `~/.android/cli/last_update_check` and
  `tos_displayed`. It may update itself outside the script's control, so SDK
  installation is less reproducible than the pinned JDK and cmdline-tools downloads.
  Analytics is off (`"hasOptedIn":false` in `~/.android/analytics.settings`).
- **Every build prints "Deprecated Gradle features were used".** The cause is
  `Configuration.setVisible`, called from AGP 9.4.1 internals (`BasePlugin`,
  `SourceSetManager`), not from this project. It is harmless until Gradle 11.
- `Unable to strip the following libraries ... libandroidx.graphics.path.so`: no NDK is
  installed, so AGP packages that Compose native library unstripped. This is harmless in
  M0. It will matter for size once GeckoView's large native libraries arrive, because
  AGP strips with the NDK's llvm-strip.
- **Editing `app/build.gradle.kts` reruns `:app:buildTwinBridge` once**, because the
  task classes are declared in that script. This is documented in SETUP.md and costs
  about 2 s.
- **Memory is the tightest resource.** Even this tiny project reaches 8.9 GB used with
  swap in use. GeckoView in M1 will grow dexing and APK merging, and the emulator
  process will grow with a real browser engine.
- **The emulator uses SwiftShader (software GPU).** That is fine for Compose
  placeholders. GeckoView rendering and video in later milestones will be slow on it,
  so frame-time numbers from the emulator will mean little.
- **Instrumented tests are slow on the first test** (10 s for the first test, then 2 to
  6 s each), mostly activity and Compose warm-up on a cold-booted emulator.
- **Extra Node versions:** nvm also has v18.20.6 and v22.4.0. `env.sh` picks the highest
  v22.x, currently 22.14.0. If someone installs a newer 22.x, it will be picked up
  automatically.
- **The machine runs a k3s server and an IDE server** (about 1.5 GB resident together),
  which the prompt's memory budget did not account for.

## 8. Questions for the planner

1. Do you accept the new Android CLI as the SDK installer, given that it auto-updates
   and Google now ships it in place of `sdkmanager`? The alternative is to download
   pinned package zips from `repository2-3.xml` with checksums, which is more
   reproducible but more code.
2. `web-ext lint` currently fails only on errors. M1 will add GeckoView-specific
   permissions (`geckoViewAddons`, `nativeMessagingFromContent`) that AMO's linter may
   flag as unknown. Should warnings fail `check`, or be tolerated with a documented
   allowlist?

## 9. Suggestions for M1

- **Repositories:** add `maven { url = uri("https://maven.mozilla.org/maven2/");
  content { includeGroup("org.mozilla.geckoview") } }` to
  `dependencyResolutionManagement`. Keep it content-filtered so other lookups do not
  hit Mozilla.
- **Kotlin alignment:** GeckoView 157 depends on kotlin-stdlib 2.4.20, which matches the
  catalog. Keep `kotlin` in the catalog as the single source. AGP 9 built-in Kotlin picks
  up KGP from the root `alias(libs.plugins.kotlin.jvm) apply false`.
- **Built-in extension path:** the extension is already at
  `assets/extensions/twin-bridge/`, so GeckoView can install it with
  `ensureBuiltIn("resource://android/assets/extensions/twin-bridge/", "twin-bridge@twinbook")`.
  For uBlock Origin in M3, keep the same `assets/extensions/<name>/` layout. Generalize
  `TwinBridgeAssetsTask` to copy several extension directories, or move both task
  classes into a `build-logic` included build, which also removes the rerun on edits to
  `app/build.gradle.kts`.
- **Manifest permissions** to add in M1 as they get used: `webRequest`,
  `webRequestBlocking`, `nativeMessaging`, `geckoViewAddons`, host permissions for the
  mock server origin.
- **ABI and size:** the emulator is x86_64. GeckoView ships per-ABI AARs (`geckoview`
  is multi-ABI and very large). For M1, either depend on the multi-ABI artifact with
  `ndk { abiFilters += listOf("x86_64", "arm64-v8a") }`, or measure per-ABI as M1
  requires. Install the NDK, or at least note the unstripped `.so` warning, when
  measuring APK size.
- **Memory:** start M1 with the current settings (Gradle 2 GB, Kotlin 1 GB, 4 workers,
  AVD 3 GB) and watch for OOM or GC thrash in `mergeDebugNativeLibs`/dexing with
  GeckoView. If Gradle needs 3 GB, lower `org.gradle.workers.max` to 3 rather than
  shrinking the AVD. A browser engine needs the guest RAM. Run `./gradlew --stop` before
  long emulator sessions.
- **Mock server:** the emulator reaches the host at `10.0.2.2`, or use
  `adb reverse tcp:<port> tcp:<port>` and `localhost`. The Node in `tools/env.sh` can run
  the mock server, so no new runtime is needed.
- **Instrumented tests:** `emulator-start.sh` already disables animations. Consider
  `testOptions { animationsDisabled = true }` too, and put GeckoView tests in `:engine`'s
  `androidTest` (its test APK already builds and runs, empty, in
  `connectedDebugAndroidTest`).
- **AGP 9 conventions seen:** no `org.jetbrains.kotlin.android` plugin (built-in
  Kotlin), and `kotlin { jvmToolchain(21); compilerOptions { jvmTarget = JVM_17 } }`
  works in Android modules. Use the new `compileSdk { version = release(N) {
  minorApiLevel = M } }` DSL. Configuration cache works with these build scripts.
- **PLAN.md updates proposed:** in section 3, record that SDK installation goes through
  the Android CLI; in section 8, mark M0 done once accepted; in section 7 or the change
  log, add the permanent KVM group fix as an owner input that is still open.
